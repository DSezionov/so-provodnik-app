# Фаза 0 — разведка данных so-wiki.ru

Дата: 2026-10-18 · ветка `phase-0-data-recon` · выборка: 50 заданий (20 разовых, 15 многоразовых, 15 подработок).
К вики ушло ≈67 запросов на 61 уникальный URL (robots.txt с повторными условными проверками, sitemap, 4 списка заданий, 5 справочных страниц, 50 заданий), пауза 5 с, всё в локальном кэше.

## TL;DR

1. **`/w/api.php` запрещён robots.txt** (`Disallow: /w/`), как и `Special:`/`Служебная:`. Значит, ни MediaWiki API, ни SMW API (`action=ask`, `browsebysubject`) использовать нельзя. Предпочтительный порядок источников из SPEC §4.1 (SMW → wikitext → HTML) **не выполним без разрешения админа**. Также `Crawl-delay: 5` — строже, чем «1 запрос/сек» в SPEC.
2. **Отрендеренный HTML оказался хорошим источником.** Страница задания собирается шаблоном `Шаблон:Задание` со стабильными CSS-классами (`quest-base-info`, `infobox-row`, `quest-process-header`, `reward money/xp/items/trade-point` …). Все поля инфобокса извлекаются на **100%** выборки, деньги/опыт сверены с SMW — **100% совпадение**.
3. **SMW-данные доступны без API**: страницы-списки (`Задания`, `Разовое`, `Многоразовое`, `Подработка`, `Персонажи`) содержат встроенный JSON результата SMW-запроса — полный список заданий (1760) с периодичностью/опытом/деньгами и 517 NPC с локациями — 5 запросов вместо тысяч.
4. **Требуемые предметы почти всегда структурированы**: шаблон `Требуется` (иконка + ссылка + «– N шт.»). Найдены в 22 из 50 заданий, количество распознано у **22/22**. У подработок количество — **диапазон «от X до Y»** (12/12), а награда указана **за единицу** — в модели SPEC это не предусмотрено.
5. **Шаги — эвристика, но с хорошей опорой**: многоэтапные задания пронумерованы «1. … 2. …» и совпадают с этапами журнала в описании (7/7). Квадрат есть у 40% шагов, явная локация — у 43%, а с учётом локаций NPC из справочника и «сдачи у конечного NPC» — у **88%**.
6. **Риск для CI**: с украинского IP сайт недоступен (блокировка провайдером), запрос из облака Anthropic получил `ECONNREFUSED`; работало только через Cloudflare WARP. Доступность из GitHub Actions **не проверена** — от неё зависит архитектура `data.yml`.

## 1. Доступ и этикет

### robots.txt (прочитан 2026-10-18, last-modified 2026-05-12)

Наш UA `ProvodnikBot/0.1 (+https://github.com/DSezionov/so-provodnik-app)` попадает в группу `User-agent: *`:

```
Disallow: /w/                 ← api.php, index.php, images
Disallow: /wiki/edit/  /wiki/history/  /wiki/purge/  /wiki/info/
Disallow: /wiki/Special:  /wiki/Служебная:
Disallow: /*diff=  /*oldid=  /*limit=250  /*limit=500
Disallow: /*action=history  /*action=edit  /*action=purge
Crawl-delay: 5
...
User-agent: ClaudeBot   Disallow: /       (также Timpibot, AhrefsBot, SemrushBot, MJ12bot)
Sitemap: https://so-wiki.ru/sitemap.xml
```

Полный разбор и правила загрузчика — в [`scraper/README.md`](../scraper/README.md). Загрузчик проверяет каждый URL по этим правилам до отправки запроса (покрыто тестами).

Отдельно: владелец вики явно блокирует `ClaudeBot` (краулер Anthropic для обучения). Наш бот — другой UA и другая цель (сборка справочника раз в неделю со ссылками на источник), но это **стоит прямо упомянуть в письме админу** и попросить согласия.

## 4. Что извлекается надёжно, что эвристикой, что нет

### Надёжно (`confidence: "wiki"`) — структурированная разметка шаблонов

| Поле | Откуда | Покрытие в выборке |
|---|---|---|
| тип, периодичность | инфобокс + SMW | 100% |
| начало: NPC + локация | инфобокс `Начало: NPC [Локация]` | 100% |
| конец: NPC + локация / «автозавершение» | инфобокс | 100% (6% — автозавершение, NPC нет) |
| предыдущие задания + статус | инфобокс, `Шаблон:Предыдущее_задание` | 100% статусов (после разбора на множество состояний) |
| явная логика И/ИЛИ между группами предыдущих | разделители `и` / `или` между списками | 2/2 случаев с >1 предыдущим |
| следующие задания | инфобокс | 100% |
| особые условия | секция `🗝️ Особые условия` | 50% заданий имеют (репутация, время суток, диалог, группировка) |
| сюжетная глава и подглавы | `Глава`, `Список подглав` | 8% |
| скрытое задание | плашка «Скрытое задание» в описании | 8% |
| совет / примечания | `tmpl-notice` (success / warning), типовые плашки «отмена задания» и «правила подработок» отфильтрованы | 4% / 8% (+ у всех подработок — «награда за единицу») |
| награды: деньги, опыт, репутация (+условие), очки торговли, очки группировки, предметы ×N | `div.reward.*` | 100%, деньги/опыт = SMW в 50/50 |
| требуемые предметы и количество | `Шаблон:Требуется` | 22/22 с количеством |
| точки на карте шага | `Шаблон:Точка_на_карте` → `data-mw-maps-mapdata` (слой + lat/lon) | 14% шагов |
| ревизия | `wgRevisionId` | 100% |

### Эвристика (`confidence: "parsed"`)

| Поле | Как | Качество |
|---|---|---|
| разбиение на шаги | абзацы «N.» в «Процессе выполнения» | 7/7 многоэтапных, совпадает с этапами журнала |
| квадрат | регулярка после слова «квадрат…» (`I3-1`, `AI7-3`, `AA2`) | 40% шагов; ложных срабатываний в выборке нет |
| локация шага | ссылка на локацию в тексте шага | 43% явно, 88% с учётом NPC/«сдачи» |
| NPC шага | ссылка на NPC в тексте | 38%; бывают упоминания не-целевых NPC (см. провалы) |
| цель убийства + количество | «убить [[Моб]] - от X до Y штук» / «убить 10 собак» | 6/6 |
| тип шага | ключевые глаголы | ≈83–95% (см. выше) |
| вариации `(Групп) X (Вез)` | префикс/суффикс заголовка | 134 задания → 40 базовых, нужно согласовать |

### Не извлекается / нужно решение

- **Квестовые предметы без ссылки**: «передайте ему образцы», «посылку весом 4 кг», «жетоны». Это предметы, которые выдаёт сама игра; в чек-лист они не попадают — и не должны (не выдумываем). В выборке такое в 7 заданиях.
- **Шаги без локации и NPC** (8 из 65): «осмотрите рацию на столе» (Мистический дом: загадка), «убить 10 собак в квадрате A2-4» — локация подразумевается (как у NPC начала), но в тексте не названа.
- **Альтернативы**: «посетить один из проходов» на 6 локациях, «можно сдать любому Управляющему на базах группировки», «информацию можно получить у Митьки, Штопора или …» — один шаг, несколько мест.
- **Описание vs процесс расходятся**: «Катим Гравы А» — в описании «от 2 шт.», в процессе «от 2 до 4 шт.». Берём шаблон из процесса.
- **Мобы**: справочника нет (страница `Мутанты` — 404); цель убийства — просто id страницы моба.

## 6. Предлагаемые изменения модели данных (SPEC §4.2) — на согласование

Нумерация — чтобы удобно отвечать «1 — да, 2 — нет…».

1. **Количество — диапазон.** `ItemReq { itemId; qty?; qtyMin?; qtyMax?; confidence }`. Для подработок игра называет точное число при взятии → в журнале дать игроку ввести фактическое количество (по умолчанию в чек-листе «20–50 шт.»).
2. **Награды «за единицу».** `Quest.rewardsPerUnit: boolean` (у всех 15 подработок в выборке). Иначе карточка покажет неверную сумму.
3. **Цели убийства — отдельно от предметов.** `Step.kills: { mobId?; mobText?; qty?; qtyMin?; qtyMax?; confidence }[]`. В чек-лист «что взять» не идут, в маршруте видны.
4. **Статус предыдущего — множество состояний.** Вместо `status?: "done"|"taken"|"unknown"`: `states: ("taken"|"done"|"failed"|"none")[] | "unknown"` + `statusRaw`. На вики встречаются «в наличии или выполнено», «выполнено или провалено», «нет в наличии и не выполнено» (= задание НЕ должно быть взято).
5. **Логика предыдущих.** Вики иногда **явно** пишет `и`/`или` между группами. Предлагаю `prevLogic: "none"|"single"|"and"|"or"|"mixed"|"unknown"` и `prevGroups` (порядок групп с разделителями). `mixed` (пример: «A **или** B **и** C») — только информирование: приоритет операторов вики не определяет. `single` — одно условие (И/ИЛИ неважны).
6. **Автозавершение.** `end?: NpcRef` + `autoComplete: boolean`. Скелет маршрута тогда: «взять у start» + шаги, без остановки «сдать».
7. **Особые условия.** `conditions: string[]` (сырой текст, показываем в карточке и в журнале). Разбор порогов репутации — не в MVP.
8. **Этапы журнала.** `journalStages: string[]` — тексты этапов, как их видит игрок в игре (совпадают с шагами 7/7). Использовать в выборе «я уже на шаге N» — игрок узнает формулировку.
9. **Несколько квадратов и локаций у шага.** `squares: string[]`, `locationIds: string[]` + `anyOf: boolean` для альтернатив («любой из проходов», «любому Управляющему»). В маршруте шаг с `anyOf` — отдельный блок «на выбор».
10. **Точки на карте.** `mapPoints: { layer; lat; lon }[]` — бесплатно извлекаются, в MVP не используем (карта вне MVP), но храним на будущее. Вес в JSON — небольшой.
11. **Скрытые задания** (`hidden: true`, 8% выборки) — их нет в игровом журнале. Варианты: (а) включать с пометкой, (б) исключить из каталога. Рекомендую (а): некоторые — обязательная часть цепочек (раздатчики).
12. **Вариации.** `(Групп) X (Вез|ЧЛ|НЗ-Т|Окр)` и `(Групп) Посылка Y (База: …)` — одно задание у разных управляющих/на разных локациях. Предлагаю `variantOf = id базового` (по шаблону заголовка, `parsed`) и выбор вариации при добавлении в журнал (как в SPEC §5.1). Задания с префиксом группировки `(Бар у ЛВЗ)`, `(Красно)` … — это **не** вариации, а разные задания (разные предметы), только сгруппированные; предлагаю `group: string` для фильтра в каталоге.
13. **Глава.** `chapter?: string`, `chapterQuests: string[]` — для показа сюжетной цепочки.
14. **Требования только из шаблона.** Ссылки на предметы вне `Шаблон:Требуется` в требования **не** записывать (это награды, выдаваемое снаряжение, упоминания). Показывать их не нужно — `rawProcess` всегда виден.
15. **Локация шага по умолчанию.** Если в шаге нет локации, но есть NPC с известной локацией (инфобокс или справочник `Персонажи`) — брать её с `confidence: "parsed"`. Последний шаг без локации → локация конечного NPC (`wiki`). Шаг совсем без опор → «Локация не определена» (как в SPEC).
16. **`description`** без пронумерованных этапов (они уходят в `journalStages`).

## 7. Рекомендации по источнику и пайплайну (Фаза 1)

- **Основной источник — HTML `/wiki/…` + встроенные SMW-результаты страниц-списков.** `mwparserfromhell` в текущем варианте не нужен (wikitext недоступен без `/w/` или `action=raw`).
- Инкрементальность: sitemap `lastmod` → перекачиваем только изменённые; `wgRevisionId` → поле `revision`.
- Справочники: NPC — из SMW `Персонажи`; локации — `Локации` (18 шт.); предметы — `Предметы` + `Артефакты`. Для неизвестных ссылок (мобы, эффекты) — либо не классифицировать (MVP), либо по одному запросу на страницу-цель с её категориями (`wgCategories`) — +N запросов × 5 с.
- **Сразу проверить доступ из GitHub Actions** (тестовый `workflow_dispatch`, только `robots.txt`). Если недоступен — варианты: (а) админ вики разрешит IP/UA, (б) сбор запускается локально владельцем, JSON коммитится, CI только деплоит, (в) self-hosted runner.
